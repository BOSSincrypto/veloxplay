## Возможности

| | |
|---|---|
| **Глобальная скорость** | Задаётся один раз — в настройках или прямо в плеере — и применяется ко всем видео, в этой сессии и в следующих. От 0.25x до 4x. |
| **Картинка в картинке** | Включается автоматически при выходе на рабочий стол. Внутри окна PiP есть пауза и перемотка на ±10 с. |
| **Мгновенная перемотка** | Переход по ключевым кадрам плюс режим scrubbing в Media3 во время перетаскивания. Между жестом и кадром нет спиннера. |
| **Жесты** | Слева — яркость, справа — громкость, вбок — перемотка, двойное касание — пропуск, удержание — временное ускорение. |
| **Фоновое воспроизведение** | Уведомление MediaSession, управление с экрана блокировки, звук продолжается после сворачивания. |
| **Память позиции** | Открывает с того места, где вы остановились (кроме самого начала и конца). |
| **Сохранение кадра** | Текущий кадр сохраняется в `Pictures/Velox`. |
| **Повтор A-B** | Два нажатия задают отрезок, третье сбрасывает. |
| **Локально и по сети** | Библиотека устройства через MediaStore плюс HTTP, HLS и DASH. |

## За счёт чего быстро

Скорость здесь заложена в архитектуру, а не включается галочкой.

**Один плеер, без IPC.** Экземпляр `ExoPlayer` живёт в [`PlayerHolder`](app/src/main/java/io/github/bossincrypto/velox/PlayerHolder.kt) и общий для Activity и сервиса воспроизведения — они в одном процессе. Play, pause и seek это прямые вызовы методов. Большинство плееров ходят через `MediaController` и платят Binder-раундтрип на каждом действии.

**Декодер не пересоздаётся.** У `PlayerActivity` объявлен полный набор `configChanges` и `launchMode="singleTask"`, поэтому поворот экрана, вход в PiP и повторное открытие того же файла переиспользуют прогретый `MediaCodec`. Именно его пересоздание даёт чёрную вспышку при повороте в других плеерах.

**SurfaceView вместо TextureView.** Кадры уходят на поверхность, которую системный композитор может отдать аппаратному оверлею. `TextureView` заставил бы копировать каждый кадр через GPU.

**Буферы настроены на задержку.** `bufferForPlaybackMs` равен 250 мс вместо стандартных 2500 мс, поэтому воспроизведение стартует почти сразу. Удерживается 20-секундный back buffer: перемотка назад внутри этого окна вообще не требует ни ввода-вывода, ни сброса декодера.

**Перемотка по ключевым кадрам.** `SeekParameters.CLOSEST_SYNC` пропускает проход «декодировать и выбросить», нужный для точного позиционирования. Во время перетаскивания ползунка режим scrubbing держит конвейер в состоянии, оптимизированном под seek, вместо полного сброса на каждое событие. Точная перемотка включается одним переключателем в настройках.

**Интерфейс не делает лишнего.** Views и view binding, никакой рекомпозиции Compose поверх видео. Тикер прогресса работает на 4 Гц, только когда идёт воспроизведение, и трогает вью только при видимом оверлее. R8 в full mode вместе с урезанием ресурсов дают релизный APK примерно на 4.2 МБ.

## Установка

APK лежит в [релизах](https://github.com/BOSSincrypto/veloxplay/releases/latest). Каждый мёрдж в `main` публикует новый автоматически.

Релизы подписаны стандартным debug-ключом Android. Это сделано намеренно: сборка воспроизводима у любого, настраивать секреты не нужно. Обратная сторона — обновиться поверх установки с другой подписью нельзя, придётся удалить старую версию или подключить собственный keystore (см. [README.md](README.md#signing-your-own-releases)).

## Сборка

Нужен JDK 17, остальное подтянет Gradle.

```bash
git clone https://github.com/BOSSincrypto/veloxplay.git
cd veloxplay
./gradlew assembleDebug
```

APK появится в `app/build/outputs/apk/debug/`.
